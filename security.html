Our approach

We try to collect as little data as possible and protect what we hold. These are the practices we use today.

Encryption in transit (HTTPS / SSL)

The website and all calls to our database are sent over HTTPS (TLS), so data between your device and our servers is encrypted.

Database access rules (Row Level Security)

Our Supabase database has Row Level Security turned on for the reports table. In plain terms:

  • anyone using the app can read reports and add a new report;
  • nobody can edit a report through the public app;
  • only a signed-in user can delete reports linked to their own account;
  • account deletion runs through a protected database function that works only for the signed-in user.

Safe API usage

  • Only a public, restricted “publishable” key is used in the browser. Secret or admin keys are never placed in website code.
  • The app talks to the database through Supabase’s API, not by sending raw SQL from the browser.
  • Values you enter are checked and encoded before they are used in a request, and text from users is shown as plain text, never run as code.

Sign-in

We use passwordless sign-in: a one-time code sent to your email that works for a short time. There are no passwords for us to store or lose.

Data minimisation

  • Message text, photos and non-link QR content are checked on your device and never uploaded.
  • Links are shortened to remove query strings and fragments before lookup, because these can contain private tokens.
  • Official verified websites are not looked up or flagged by the community check.

Your part

  • Never share your one-time code. We will never ask for it.
  • Sign out on shared devices; clearing browser data removes local history.
  • Keep your email account protected with a strong password and 2-step verification.

Limits

No system is perfectly secure, and we cannot guarantee that unauthorised access will never occur. If a breach affects your personal data, we will tell affected users and the authorities as required by law.

Report a security problem

If you find a vulnerability, please email pritam44760@gmail.com with the details and give us reasonable time to fix it before sharing it publicly.
